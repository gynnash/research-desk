# Agent Memory 定时研究任务 MVP

修订：2026-10-30，版本1.1。本文只描述当前使用的流程；早期PR自动合并和跨轮积压队列方案不再作为实施要求，历史版本可从Git记录查询。总体目标见[三Agent架构](three-agent-architecture.md)，差距见[目标对齐审查](workflow-alignment-2026-10-30.md)。

## 一轮做什么

GitHub Actions触发 → 配置的自托管主机采集与查重 → Research正文分析与独立审阅 → Insight比较历史、生成报告、洞察与选题并独立审阅 → 确定性准入 → 可信发布job新增正式资料到main → 现有Git同步到Obsidian。

日常研究入库无需人工逐篇审阅。Writing另须用户在真实页面明确确认选题、角度、受众和证据版本；生成大纲、初稿、候选稿后逐阶段审阅，正式三稿仍通过单独准入保存。模型不能批准自己的写作，系统不发布公众号。

## 资料发现与挑选

- 每轮重新扫描最近60天首次发表的候选，不按完整扫描游标缩小窗口，不读取旧轮次pending来抢占名额。
- 当前仅接入arXiv、Letta和LangChain。arXiv用官方API的submittedDate日期查询，每页20条，每来源最多80个候选；博客仅扫描公开列表，未实现可靠的两个月归档遍历。分页未完成、抓取失败或范围未知必须如实记录。
- 主题关键词来自[research_topics.yaml](../config/research_topics.yaml)。仅词面涉及GPU内存等无关内容不入选。
- 先排除全历史已挑选身份，再全局按可核实社区关注度选择最多5份，取消单来源2份配额。URL去跟踪参数，arXiv abs/pdf/html/版本归同一论文身份，DOI按现有规则规范化；不新增身份数据库。
- 热度为HF推荐与HN原文匹配讨论的透明观察值，保留指标、时间、请求来源和散列。每轮最多240次provider lookup；未知不当零热度，不足不凑数。它只是已扫描候选中的关注度排序，不是全网最热或技术质量排名。
- 知乎、X、Reddit、Quora尚未接入，不能通过填写网址冒充支持；授权、可访问范围与后续适配边界见[对齐审查](workflow-alignment-2026-10-30.md)。

## Research与Insight

Research固定arXiv版本，优先官方HTML，缺失时提取同版本PDF，确实失败才摘要降级。按章节/页码组织证据；生成与审阅读取相同正文、范围和定位，修订不换证据。论文最多120,000字符，博客目前仍为最多6,000字符的节选；超出正文预算标记excerpt，不能伪称全文。详见[全文阅读](fulltext-reading.md)。

单篇研究说明问题、方法、主张、证据、适用条件与局限；区分原文事实、作者声称和推断。正文获取不等于分析足够深入，更不等于复现实验；当前新版深读效果尚待下一轮真实结果核验。

Insight从过去180天按真实研究日期和月份抽样最多30份历史文件，含来源依赖。输入区分已准入历史AI、人工笔记和人工改写，并保留原文发表日与计划研究日；后者不是实际执行时刻。综合报告披露实际覆盖日期、跨度、文件和来源数。当前真实资料仅积累十余天，不能声称已观察半年趋势。

使用现有comparisons、insights、open_questions和validation比较观点共识、分歧及时间变化，提出深度看法和待深入问题，不新增Trend Agent。趋势需要跨时间、跨独立原始来源与替代解释；证据不足时只称线索或假设。同一原文的多份笔记不算独立验证，历史笔记也不升级为本轮原文核验。

## 审阅、预算与失败补跑

| 项目 | 规则 |
| --- | --- |
| 独立性 | YAML指定生成与审阅的不同实际model ID、独立上下文；缺失审阅不自审、不默认通过 |
| 结果 | pass后仍须确定性校验；revise仅修订一次并重新审阅；reject不入库；blocked保留原因与恢复条件 |
| 轮次预算 | Research最多12次，Insight最多4次，总计16次；5份正常研究/审阅共10次，不能保证每份都可修订 |
| 共享预算 | [membership_budget.yaml](../config/membership_budget.yaml)每月100次，历史消费不清零；本地门禁不是官方会员余额 |
| 输入输出 | 单次实际输入最多500,000字符，输出最多8,000字符，等待最多120秒；超限停止，不静默丢弃审阅依据 |
| 请求未知 | 调用前预留预算；超时等未知结果不返还预留、不盲目自动重发 |
| 同轮恢复 | 沿用稳定cycle_id、冻结配置、窗口、原文、身份和已有阶段；不换ID重置判断、修订次数或预算 |
| 已选失败 | 回原轮次补跑，不在下一轮作为新资料重复挑选；定向全文升级或实质更新用显式批次另存报告 |
| 关联恢复 | 需要补Insight时使用[有限关联补跑](linked-insight-recovery.md)，保留原Research与失败现场，不能重做已完成研究 |
| 漏触发 | 沿用现有时间槽catchup配置；补跑已绑定轮次保留原策略，新规划按滚动窗口发现，超出窗口不声称自动补齐 |

旧轮次保留原配置和prompt版本，新策略不回写历史回执。来源失败不等于没有新资料；合法的无候选结果可以只保存检查点，不能用旧报告充当新成果。

## GitHub入库与Obsidian阅读

模型只返回结构化内容，不直接写Git。研究检查点先保存在各方向test；[确定性准入](formal-admission.md)核对输入、审阅和输出散列，只创建允许的正式文件。独立可信publisher校验后普通提交推送main；当前不需要机器人PR/自动合并流程。冲突、人工编辑或仓库规则阻止写入时保留现场，不覆盖、不强推、不修改仓库规则。

新策略来源卡只保存身份、原文和详细研究链接，单篇分析留在reports，避免同文重复。综合报告、洞察和选题各在对应方向目录。正式资料与人工笔记不因新研究被改写；历史摘要保留，定向深读另存更新。**原文全文目前仅在内存，尚未满足全文副本归档到Git。**

发布成功后在本地派生一份[正式资料索引](../workbench/资料索引.md)随成果回存，worker不能提交workbench文件。自动区被人工改写或索引生成失败时保留内容并提示，不阻断合格研究保存；区外人工内容保持。Obsidian读取同一套Markdown，[研究首页](../研究首页.md)保持稳定导航，Sync到手机仍由用户配置。
