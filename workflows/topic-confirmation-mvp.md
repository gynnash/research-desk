# 真实选题确认入口 MVP

2026-10-19 设计稿，**尚未实现入口，也未确认任何真实选题或启动会员 Writing**。自动 Research → Insight → 独立审阅 → 正式入库继续按既有配置运行；本设计只补上“用户选定要写什么”这一环。沿用 Markdown、YAML、Git 和当前本地/远程会员主机，不建设线上平台或数据库。

## 首版交互

**唯一默认入口是轻量本地确认页：先展示完整预览，再由用户直接点击确认。** 页面仅监听 `localhost`，使用 Python 标准库 HTTP 服务和静态 HTML，不建设登录平台或引入数据库。Codex / ChatGPT Work 接受“列出待确认选题”“预览这张卡”等自然语言请求，帮助打开页面；用户不需要复制命令。Obsidian 继续用于阅读选题卡和证据，修改卡片状态、打勾或添加“同意”都不直接授权写作。

未来若宿主能向确认程序提供可验证、直接来自用户的消息事件，再增加自然语言确认适配。模型转述“用户已同意”、模型输出 `confirmed`、静默、研究任务的既有授权，均不能替代这个事件。未完成宿主来源验证前，不把聊天里的模型回复当成确认入口。

预期流程如下，页面与服务均尚未实现：

1. 待确认列表只显示已正式准入、仍为 `proposed` 的卡片，显示标题、方向、生成日期及证据范围。
2. 用户打开一张卡，查看标题、写作角度、受众、目标字数、证据与缺口、三阶段范围、生成/审阅模型、调用上限及“不会发布公众号”。调整角度、受众或字数后刷新冻结预览包，不修改原选题卡。
3. 用户查看最终预览，勾选范围说明，再点击“确认并排队写作”。不预选同意、不提供默认或批量批准；模型与 CI 不得代点。确认只允许这个版本执行一次 `outline → draft → candidate`。
4. 受信任入口保存确认事件并同步 Git 后，为会员主机排队同一写作批次；恢复、查看、撤回均引用这个确认 ID。首次接入会员时先只写 `test`，验收后再另行启用正式文章准入。

当前可用于后续预览的是[正式选题卡](../articles/agent-memory/cycle-agent-memory-gh-20261019-topic-1.md)。它仍未确认：其中 R1 只阅读论文摘要，R2 只阅读博客节选，历史 H1 保留历史基线身份。预览必须展示这些缺口；选择这个题目不会自动补全文或宣称已核实评测结果。

## 确认绑定与准入检查

预览包是给用户审阅的冻结输入，确认不能仅绑定一个易变的标题或 ID。建议记录以下字段；这里仅规定 Schema，不创建真实批准样例：

| 绑定 | 必需内容 |
| --- | --- |
| 仓库与选题 | 工作台稳定 ID、方向、选题 ID、规范相对路径、当前文件 SHA-256、基线 commit。 |
| 用户选择 | 最终标题、角度、受众、目标字数，以及这些字段的规范序列化散列；若调整观点超出证据范围，先补证据或返回 Insight，不直接写作。 |
| 证据与审阅 | 精确的来源、Research 报告、洞察及历史基线路径/散列；来源规范 URL、版本、阅读范围；独立审阅回执、准入计划、`accepted` 回执及其 SHA-256。 |
| 执行范围 | 大纲、初稿、候选稿三个阶段；Writing 配置/提示词版本、生成和审阅 model ID、批次/阶段请求上限、最多一次修订；`publish_authorized: false`。 |
| 确认来源 | 预览 ID 与散列、确认 ID、UTC 时间、`origin: local_confirmation_page`、明确操作及本地会话事件 ID；不保存聊天全文、主机绝对路径或秘密。 |

只接受在 `main` 上可追溯的正式选题：必须核对独立生成/审阅 model ID 不同、审阅 `pass` 绑定当前候选与输入、准入回执 `production_accepted: true`、选题属于准入输出。不能因为卡片正文写了“通过审阅”或存在 `accepted.yaml` 文件就放行。

读取正式来源时使用准入模块验证后的有效输出散列：已有[机械链接修复记录](formal-admission.md)须连同原始计划和回执一起验证，不能绕过历史记录直接信任新文件。人工历史资料作为 `human_baseline` 绑定当前文件散列，不伪造模型通过记录。

确认前、每次模型请求前、每个产物创建前重新检查这些绑定及最新撤回事件。相关输入、角度、受众、配置或审阅变化时追加失效事件，停止并重新预览确认；`main` 新增无关文件不使确认失效。手工改动证据后也不能沿用旧确认。

## 人类授权与不可变记录

模型生成/审阅进程只接收冻结证据包，不提供确认工具、确认目录写入能力或页面控制。手写 YAML、`origin: human` 标签和文件 SHA 都不能证明人类操作。首版由用户控制的受信任本机确认进程采集明确点击，写出事件；不引入账号平台、私钥或公钥管理。Git 和本机写权限是信任前提，不能抵御有相同本机权限的恶意代码，不能宣称 SHA 证明真人。

页面服务仅允许列出、预览、确认和撤回，不持有会员令牌、模型调用或公众号发布能力。只绑定环回地址；校验 `Host`、同源 `Origin` 和每次启动随机会话 CSRF token，状态变更只允许 `POST`。每个冻结预览有短时、一次性 nonce，确认时核对当前散列并原子消费；刷新、双击、过期预览和跨站请求不能创建第二个确认。确认和撤回均展示明确结果，不把页面打开或请求 `GET` 当作批准。

建议记录路径为 `reports/<topic>/writing-approvals/<approval-id>/`，仅追加 `preview.yaml`、`confirmed.yaml`、`revocations/<event-id>.yaml`、`invalidations/<event-id>.yaml` 和 `claims/<batch-id>.yaml`，各自配对 SHA-256。撤回、失效和执行占用关联原确认 ID，不改写原确认或选题卡。状态由有效事件推导，不在多个文件中反复修改 `approved: true`。nonce 和 CSRF token 仅保存在进程内存/本机会话，不提交仓库。

确认拥有一个稳定批次 ID。执行前创建不可重复占用记录，同一确认的再次启动只恢复原批次，不生成第二篇文章或刷新预算；已完成后需新预览、新确认才能另写一篇。撤回同步到共享 `main` 并在下一次执行检查读取后，阻止后续请求或落盘；已经发出的请求可能仍消耗会员用量，返回后保留检查点与账本，产物不得自动继续入库。撤回不删除既有稿件，也不授予发布权限。

## Writing、预算与恢复

沿用[离线 Writing](writing-agent-offline.md)的顺序和证据规则：大纲 → 初稿 → 发布候选稿，每阶段先做确定性校验，再由不同模型、独立上下文审阅；通过才继续。区分原文事实、作者主张、我们的推断及通俗比喻，保留原文与报告引用，不将摘要、节选升级为全文核查。每阶段最多修订一次，仍不通过即停止。

正常三个阶段为 6 次调用，含修订复审最多 12 次；使用 YAML 中更严格的实际批次/阶段限制，并与 Research、Insight 共用[会员请求预算](membership-budget.md)，不另开账本逃避每月上限。会员凭据仍在既有仓库外 profile；GitHub 发布步骤不读取它。执行预算不足时先停止，不因人工确认而突破限制。

首个真实会员验收仅新建 `articles/test/<topic>/<batch-id>/{outline,draft,candidate}.md`，回执与请求事件放 `reports/test/<topic>/writing-runs/<batch-id>/`。真实确认记录使用独立的真实授权目录，不能由 `confirm-fixture`、`origin: offline_fixture` 或 mock 回执升级而来；生产输入也不能读取测试稿为正式证据。真实会员调用与模拟次数分别记录。

恢复沿用原确认、批次、冻结输入、请求预留和检查点；通过阶段直接复用，未知请求不盲目重发。完成的缓存重放不增加调用。已有稿件若被人工编辑则停止，保留两份内容；不覆盖旧稿、不重新生成后替换。正式文章准入后沿用 create-only，每阶段另存新文件，候选稿始终没有公众号发布授权。

## Git 同步、部署与配置

当前 Mac 提供本地页面，既有 Git 同步方式保持不变。确认器使用与执行器分离的干净工作目录，先核对并同步 `main`，记录所用 Git 基线，在单工作台锁下创建新记录并普通提交推送；不在 Vault 中自动暂存用户改动。存在同名冲突、输入变化或非快进推送时停止并保留确认现场，不强推或自动解决人工笔记冲突。确认只有保存到共享 `main` 且再次校验后才能派发写作，不能仅凭本地未同步文件在远端执行。

Writing 使用现有唯一会员执行通道与 Research 共用串行队列；不能一边在 Vault 调用会员、一边让 runner 并行运行。确认器只排队，执行器在独立工作目录复核最新确认、撤回和输入，实际请求记录与研究共享预算。远程部署也仅监听该主机环回地址，用户通过自己的安全连接/端口转发打开页面，不直接暴露公网；每个用户在执行主机自行完成官方会员授权。单执行器首版不做多主机账户协调。

后续 `config/writing.yaml` 提供方向、会员后端、模型、预算、字数范围和输出阶段；入口配置仅暴露工作台 ID、本地端口和可信入口类型，不含 OAuth token、会话 token 或个人绝对路径。路径固定在本方向允许目录，配置不能放宽覆盖、确认或发布边界。公开仓库提供未启用的示例，用户自行部署和登录。

## 实现顺序与少量验收

1. **只读预览和绑定**：解析一张真实正式卡，校验准入及有效散列，展示证据缺口、角度/受众和预算；不创建确认或调用模型。输入变化时旧预览不可确认。
2. **用户确认和撤回**：实现 localhost 页面、同源/CSRF/nonce、追加记录、一次占用和 Git 保存。用隔离样例验证跨站/过期请求、mock 批准、重复执行、撤回及证据变化均不能越过门禁；不替用户确认真实题目。
3. **小额度会员 Writing**：用户实际确认一张卡后，再接入既有会员主机；默认只写 `test`，验收一次大纲/初稿/候选稿及一次缓存恢复，核对真实账本，不重复做大规模测试。
4. **正式文章准入**：测试通过后单独启用 create-only，确认、证据、独立审阅和 Git 回存均可追溯。自然语言直接确认适配、GitHub 手动入口和托管网页平台按需求后置；公众号发布仍是单独授权的未来能力。

本轮只保存设计，不创建页面服务、以上配置、真实确认、写作任务或新调度。当前所有真实选题保持待人工确认。
