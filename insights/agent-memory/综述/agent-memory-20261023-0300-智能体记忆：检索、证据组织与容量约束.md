# 智能体记忆：检索、证据组织与容量约束

检索到相关记录之后，怎样把它们组织成足以回答问题的上下文？这是本轮材料最值得继续追问的地方。有限预算下的选择、去冗余与信息完整性彼此牵连：保留更多内容未必更有用，压缩得更少也未必更正确。现有材料提供了两个研究方向，但尚不能说明哪种策略已经更好。

## 从检索命中走向证据组装

面向长期对话记忆的查询条件证据编译，先定位支持材料，再在预算内挑选互补证据并组织回答上下文。它把问题从“哪条记录相关”推进到“哪些材料合在一起能支持回答”。论文摘要报告了 LoCoMo 结果，但实验设置、成本定义和统计不确定性尚未核查。

历史上下文管理笔记记录了文件卸载、摘要和按需加载，Memory Blocks 笔记则描述按用途和容量组织记忆。它们提示可以区分持久组织与查询时组装，但不能据此认定两者互补。编译过程也可能漏掉必要信息，增加延迟和成本；应检查它与原有摘要、卸载机制组合时，是否进一步丢失信息或产生冲突。

## 容量约束值得单独评测

另一篇视频编辑摘要描述在固定预算下缓存前序帧特征，按相似性检索传播，并依据多样性更新缓存。这个例子可以启发容量问题，却不是通用智能体记忆实验。视频特征的多样性，不等于对话事实的价值、可信度或时效性。

因此，相关性与冗余控制能否帮助有限记忆保留有用信息，仍需另行检验。固定容量本身不保证质量，去冗余还可能删掉低频但关键的信息。写入、遗忘、冲突更新和长期正确性，目前也没有共同评测可供比较。

## 下一步怎样检验

可先固定模型、长期对话任务和上下文预算，对照直接呈现检索结果与证据编译，由盲评者检查答案正确性、支持完整性和无关信息比例，同时记录延迟及 token 成本，并在多个数据集、随机种子下重复，公开失败案例。容量实验则保持检索、回答组件一致，比较重要信息保留、过时与冲突处理、存储成本，用跨会话任务及人工核验的事实来源标签检查误删风险。

本轮两篇论文均只读摘要，历史博客笔记未重新核验原文，未复现实验。尤其不能把视频编辑中的缓存策略直接迁移为智能体记忆结论；不同来源也不互相验证效果。以上是研究线索，不是跨领域性能排名、因果结论或已确立趋势。
