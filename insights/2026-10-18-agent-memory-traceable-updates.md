# 洞察：用途分明有助审阅，摘要更新仍需可追溯

日期：2026-10-18

主题：Agent Memory

状态：研究假设，待手动验证；AI 辅助整理，待用户复核。

## 观点

对长期积累的研究资料，原文依据和当前摘要应各自可定位；摘要变化时，最好能解释改了什么、依据是什么、原判断为何不再适用。用途和权限明确，可能方便检查，但不能替代事实核对。

## 事实依据与推断

[Memory Blocks 原文](https://www.letta.com/blog/memory-blocks/)介绍用途标签、只读块和共享块，见 [研究报告 E2](../reports/2026-10-18-agent-memory-memgpt-memory-blocks.md)。这些是组织和权限机制，本报告没有从中找到足以验证“更新必然正确”的对照结果。

我们的治理推断是：ResearchDesk 可以让原文记录、综合判断和文章表达分别可追溯，再用修改原因连接不同版本。这个建议借用了用途分明的思路，不表示 Markdown 文件夹等同于运行中的记忆块，也不表示原文已提供来源追踪或冲突解决方案。

## 适用条件、反例与置信程度

适用于摘要持续修订、多人接力或需要审阅历史判断的研究。只读内容也可能已经过时；多个用途清楚的记录仍可能重复、矛盾。标签和 Git 历史本身无法判断真假。

定性置信程度：对原文所述组织方式高；对本库治理建议中等。没有已执行的纠错演练或长期效果证据，等级不是统计置信区间。

## 少量手动验证方案

尚未执行。另建明确标为虚构的临时练习记录，模拟四种更新：新增依据、修正旧摘要、两条证据冲突、缺少依据。每次检查能否找到原始记录、保留修订原因，并让未解决冲突继续可见。

若只能看到最新结论，却无法解释其变化，就记录为审阅链路缺口。练习结果只评价流程是否可检查，不作为论文实验或产品能力证明；虚构内容不得混入真实资料。
