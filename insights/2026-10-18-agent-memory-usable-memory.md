# 洞察：把“保存过”与“需要时能用”分阶段验收

日期：2026-10-18

主题：Agent Memory

状态：研究假设，待手动验证；AI 辅助整理，待用户复核。

## 观点

对研究材料的使用，可以分别检查保存、找到、进入本次输入、正确使用四个环节。一次回答失败时，先定位断点，再决定补资料还是修改整理方式。这是本库提出的检查方法，不是已经验证的通用标准。

## 事实依据与推断

原文依据见 [研究报告 E1、E3](../reports/2026-10-18-agent-memory-memgpt-memory-blocks.md)：[MemGPT §2](https://arxiv.org/html/2310.08560v2)要求窗口外信息调入当前上下文；[§3.2.1](https://arxiv.org/html/2310.08560v2)报告检索可能提前停止。

我们的推断是：用资料数量或“文件已入库”作为唯一验收条件，难以解释下游写作是否用了合适证据。将环节分开，可能让失败更容易检查。这里没有证明这种方法会提高准确率或降低成本。

## 适用条件、反例与置信程度

适用于资料跨文件、跨版本，且回答需要来源依据的任务。若所需内容已完整处于当前输入中，额外检索未必有益；错误或无关内容即使被取回，也可能导致错误判断。

定性置信程度：对原文机制描述高；对本检查方法的实用价值中等。后者尚无本库实验支持，等级不是统计置信区间。

## 少量手动验证方案

尚未执行。使用现有两份来源，预先固定六问：

1. 两个事实题：论文首次发表日期是什么？本次阅读哪个版本？
2. 两个跨资料题：两份材料如何关联？论文评测能否直接证明博客的后续设计有效？
3. 两个未知题：共享更新冲突怎样处理？此路线能否保证多年使用可靠？

每题记录所找资料、证据段落、实际采用的证据和答案是否越界；没有依据时记录“未回答”。如果后续有模型参与，还需另外记录实际输入，不能把人工证据包等同于模型已看见。结果只用于流程排查。
