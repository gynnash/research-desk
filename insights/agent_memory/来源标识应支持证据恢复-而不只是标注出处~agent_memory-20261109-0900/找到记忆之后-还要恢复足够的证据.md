# 找到记忆之后，还要恢复足够的证据

本轮最重要的判断是：检索命中不等于记忆可用；系统既要保留查回原始证据的路径，也要单独优化交给回答模型的内容。

MemCompile 提供了最直接的受控证据。在 LoCoMo 上，作者固定入选来源及顺序，来源召回率均为85.50%，只改变呈现方式：每个来源仅给一条代表事实、提供原始对话、提供该来源全部保留事实时，模型裁判准确率分别为57.01%、75.32%和80.52%。生成组件使用 gpt-4o-mini，裁判为 gpt-5-nano。这说明正确来源已经找到后，过度压缩仍会损害回答；整理后的事实束又可能优于原文。作者将后者解释为保留限定条件、减少对话噪声，但事实束只能覆盖抽取后留下的信息，不能恢复写入时的遗漏。

MFM 与之相同，都把定位线索和实际证据分开；区别在于，MFM 允许智能体回看历史画面，而非只读取已抽取事实。作者报告，在 Minecraft Dragon 任务、36,000步预算及三个随机种子下，GPT-6-Astra 配合完整 MFM 平均完成16个里程碑，移除历史画面后降至9.7个，任务仍未完成。这个消融支持原始视觉记录有用，但总体优势还涉及索引、程序和记忆巩固，不能全部归因于画面回看。

历史研究《Memory Tax: Dissecting the Net Value of Agent Memory》已区分写入丢失与访问困难：部分系统直接获得理想记忆证据后接近理想原文成绩，正常检索却明显较差。此次 MemCompile 进一步隔离了证据呈现问题。历史 MemComposer 则固定所选经验，仅改变顺序，作者报告在 Ministral 执行器的100个客服任务上，学习顺序比四种规则排序高出3.8—8.5个平均成功率百分点。两者分别考察对话问答和行动经验，不能合并为同一种收益，但都说明检索之后仍有独立的优化空间。

另一篇本批 MemoryTax 的结论边界更窄：仅测试一段可完整放入上下文的历史、152题，每配置运行一次；搜索智能体还比其他方法多看到了照片说明。因此，它不足以证明按需搜索普遍胜过记忆系统。上述结果均为作者报告，未独立复现，也未验证长期在线更新中的收益。

## 来源标识应支持证据恢复，而不只是标注出处

我们的推断是，稳定的来源关联可以成为修复接口：先比较理想原文与理想记忆，判断信息是否在写入时丢失；再固定来源，比较精简事实、事实束和原文，定位呈现损失。前者失败应补写入或回查原文，后者失败才适合调整上下文。仅增加检索数量，无法针对这两类问题修复。

## 压缩程度应按用途分开决定

用于定位的线索可以很短，供回答或行动使用的证据则需要保留关系、时间限定及必要顺序。由此可推断，不宜用同一份摘要同时承担检索和决策。验证时应固定候选或来源，单独比较展开方式与排列，并计入额外处理成本；这比只看整体准确率更能判断加工是否值得。
