# MemoryTax: The Bitter Lesson of Agent Memory


MemoryTax 研究的不是如何新增记忆模块，而是模型具备自主检索能力后，预先抽取事实或构建知识图谱是否仍值得。作者在一段含419轮对话、152个问题的 LoCoMo 记录上，比较七种方法与三种模型，联合核算建库和回答成本，并通过交换记忆写入者与读取者检验信息损失。结果中，Mem0 只在最弱模型上超过全文输入，强读取者也难以弥补弱写入者留下的缺口；Pi 配合最强模型以6.95美元取得99%正确率。但其领先多数来自独享的照片描述，无照片证据的问题上，它与全文输入仅差一道。研究的重点因此是写入损失、检索能力与成本摊销之间的取舍。

## 比较的核心是何时决定保留什么

这项研究没有提出新的记忆架构，而是比较两种信息选择时机：Mem0、Zep 在问题到来前把对话转成事实或图谱，编码代理则保留原始记录，收到问题后再用工具读取。实验使用 LoCoMo 的 conv-26：19个会话、419轮对话，包含70道单跳、32道多跳、37道时间和13道开放域问题，排除对抗问题。七种方法分别搭配 GPT-4o-mini、GPT-6 Luna、Claude Opus 5.5，形成21个实验单元。全部历史都能装入各模型上下文，因此全文输入是可行基线，而不是因长度限制被迫放弃的方案。

各方法改变的是从历史到回答上下文的通路。全文输入直接提供全部记录；BM25 保存原始轮次，取排名最高的8轮及各自前后2轮。Mem0 OSS 2.1.0 按时间顺序逐轮写入，文本前附日期，回答时最多取200条事实，不重排。Zep 使用 Graphiti OSS 0.30.2，在 Kuzu 上以每个会话为一个 episode 建立时序图，再用混合边检索取前20条边。通常由同一个模型负责建库和回答。这意味着读者实际接触的不是完整历史，而是写入阶段生成、再经检索筛选的表示；具体抽取与检索配置采用默认设置。

Pi、Codex 和 Claude Code 则为每道题启动全新会话与容器，容器内只有官方对话 JSON，没有题库或答案；模型依靠默认工具读取文件，最终消息作为答案。因此，这里测到的是对持久原始记录的逐题访问，不是代理跨题积累经验。较强的两个模型均使用 high 推理强度，代理关闭网页搜索，容器只能访问模型端点。一次 rollout 包括建库及全部152题；正确率由 GPT-4o-mini 按宽松评分规则判定，空答案算错。成本覆盖语言模型与嵌入调用，但排除裁判；失败或未产出答案的尝试会重跑，只计入被接受的尝试。

## 记忆收益随模型改变，建库成本却先发生

作者报告，GPT-4o-mini 下 Mem0 的正确率为78%，高于全文输入和 BM25 的74%，Zep 为43%；代理则只有 Pi 的63%、Codex 的28%和 Claude Code 的29%。行为记录提供了重要解释：Codex 约四分之三的问题会打开文件，Claude Code 几乎不打开，否则便仅凭问题作答，说明工具可用不等于模型会使用。换成 GPT-6 Luna，全文输入达到92%，Mem0 为80%、Zep 为51%；换成 Claude Opus 5.5，Mem0 与全文输入同为95%，Zep 为87%。这些结果支持的是本次设置中结构化记忆的收益依赖模型，而非所有代理天然优于记忆系统。

作者把预处理开销称为“记忆税”：Mem0 在三个模型上的建库费用分别约为0.56、0.45、25.88美元，已经超过同模型全文输入完成整轮问答的0.43、0.29、17.84美元。虽然 Mem0 单题更便宜，但按本次价格和调用成本，须在同一历史上回答372、545、596题才能摊平建库费用，而实验只有152题。因此不能只比较检索后的单题开销。作者报告，Mem0 和 Zep 均未进入成本—正确率前沿，前沿由 GPT-6 Luna 的 BM25、全文输入，以及 Claude Opus 5.5 的 Pi 构成；这同时保留了大量问题共享同一历史时，预建记忆可能划算的条件。

## 交换读取者后，写入损失仍然存在

为分离写入能力与回答能力，作者固定各模型生成的记忆及其检索结果，再让另外两个模型回答；检索本身不调用语言模型。Zep 使用 GPT-4o-mini 写出的图时，三个读取者依次取得43%、43%、45%；改用 Claude Opus 5.5 写出的图，则分别为66%、71%、87%。Mem0 的差距较小，但同样存在：弱模型写入后为78%、83%、84%，最强模型写入后为89%、91%、95%。作者据此认为，升级读取者无法恢复写入者遗漏的信息。严格说，观测对象是“存储表示加检索结果”的整体瓶颈；实验没有逐项标注哪些事实在抽取或检索环节丢失。

## Pi 的成本优势与准确率优势需要拆开

作者报告，Claude Opus 5.5 驱动的 Pi 以6.95美元完成一轮，正确率99%；同模型全文输入为17.84美元、95%。Pi 每题约读取10,000个输入 token，其中7,900个来自缓存，全文输入约为28,900个。同模型的 Codex、Claude Code 分别取得98%、97%，但花费25.41、28.41美元，说明代理外壳和访问流程也影响总账。Pi 唯一被判错的问题涉及绘画分享者：答案键把 Melanie 分享的画记到 Caroline 名下，Pi 指出 Caroline 分享的是 drawing。作者认定这是答案键错误，其他三个使用最强模型的相关方法也指出同一错误并被判错。

不过，作者明确承认两类方法没有获得完全相同的信息：代理读取的官方文件包含照片描述，记忆方法只得到轮次文本。419轮中有116轮附照片，152题中64题的证据位于这些轮次。最强模型下，Pi 比全文输入多答对七题，其中六题属于照片证据组。另88题中，Pi 为100%，全文输入、Mem0、Codex 和 Claude Code 均为99%。这项拆分把结论收窄为：在无照片证据的子集上，Pi 与全文输入只差一道，而整轮花费不到其一半；它不是把照片描述补给所有方法后的受控重跑，因此仍不能证明搜索原始记录比通读完整记录更准确。

这提示，工程选择不宜简化成“要不要记忆”，而应区分原始记录是否保留、何时压缩，以及由谁决定取用哪些信息。预先抽取可以减少重复输入，却把未来问题的可回答范围绑定到既有表示；保留原文并按题搜索，则把选择工作推迟给读取模型，但前提是模型确实会调用工具，且代理执行成本受控。结合弱模型的工具使用失败和强模型的费用差异，我们据此推测，更值得比较的是模型、表示和访问流程的组合，而非孤立的记忆模块名称。作者提出改进原始记录上的精确、语义与向量搜索，这在本文中是研究方向，不是已经完成的模块消融结论。

## 适用条件与仍需验证的问题

已阅读抽取全文，未独立复现实验。材料包含正文、结果表文字、协议和提示词附录，但文本抽取不能核验图形、版式及公式渲染，也可能遗漏未被文本化的图表信息；本文未据图形补推额外数值。

实验仅覆盖 LoCoMo 十段对话中的一段，每个单元只有一次被接受的运行，未报告重复运行方差；失败尝试重跑且不计入所报告成本。裁判是使用宽松规则的 GPT-4o-mini，且至少存在一个错误答案键，因此几个问题的正确率差距和实际重试总成本均需谨慎解释。

所有历史均可放入上下文，代理独享照片描述，Mem0、Zep 使用默认配置，费用依赖标价与缓存。这些条件限制了对超长历史、其他基准和配置的外推；照片子集拆分不能代替统一输入后的重跑。实验也未检验持续更新、遗忘、跨题学习、隐私安全或长期在线维护，不能据此否定这些需求下的记忆架构价值。
