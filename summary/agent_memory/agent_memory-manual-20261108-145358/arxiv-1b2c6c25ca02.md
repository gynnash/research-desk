# MemSteer: Turning User Histories into Supervision for Agent Memory Optimization

个人历史通常没有天然的任务成败信号，导致智能体难以判断该如何调整存储、检索和上下文组织。作者提出 MemSteer：先从关联记录中规划答案及证据组合，再生成问题，通过语义审计与盲答恢复筛选监督数据；MemSteer-Opt 随后利用答案评分和证据缺失位置诊断失败，迭代修改记忆设计而不更新模型参数。作者报告，ATM-Bench 主集 Question Score 从54.9升至68.3，RHELM 在有、无外部数据时也取得改善。最值得关注的是，历史生成的监督既能服务不同优化器，也能支持新用户继续适配，但共享设计并非总能直接迁移。

## 将个人历史变成可评分、可追因的监督

作者提出，个人记忆优化的瓶颈不只是信息检索，而是缺少判断设计好坏的反馈。对话、邮件和文档不会自然提供任务成功标签，而不同用户的内容与组织方式又使统一设计难以普遍适用。MemSteer 因而从未标注历史生成“问题、参考答案、来源证据”三元组：答案用于评价候选设计，证据用于解释答错发生在哪个环节。它区别于用合成问答奖励训练记忆构建模型，也区别于针对问答失败直接修补记忆库；作者要优化的是记忆系统的组织和使用规则，整个过程不更新模型参数。

监督生成不是随机拼接记录后直接出题。作者先将历史组织为来源记录图，保留原文、标识符和结构元数据；同一会话、相邻文档章节、显式引用或足够词汇重叠都可形成边。系统从种子沿路径扩展，在上下文预算内抽取连通材料包。随后，LLM 规划器明确要问什么、参考答案是什么、每项事实对应哪个来源片段，以及每条记录如何参与事实组合。计划必须通过结构一致性和来源覆盖的程序检查，才交给独立的问题生成步骤。这里的图服务于监督材料采样，并不意味着最终记忆检索必须采用同一张图。

作者再用两层检查阻止错误监督进入优化循环。语义审计同时查看材料包、答案计划和问题，分别检查事实是否有来源支持、记录贡献是否成立，以及问题是否符合计划；全部必要判断通过后，盲读器只获得问题、答案类型和材料记录，不看参考答案。它必须判断可回答，恢复出经类型归一化后完全一致的答案，并引用每条选定证据记录。列表按集合相等检查，数值要求值与单位一致。通过的数据再划分为互斥训练集和验证集，分别用于提出修改与选择设计，避免用同一批失败案例同时承担全部决策。

## 通过证据位置区分存储、检索与回答失败

MemSteer-Opt 将设计拆为存储、检索和上下文构造三部分：先按当前存储规则从历史构建记忆，再检索相关记录、组织上下文并交给固定回答器。训练问题答错时，系统首先检查所需记录及引用片段是否完整进入最终上下文；若已齐全，标记为回答失败。若证据缺失，则按来源标识检查当前记忆能否恢复这些记录：任一缺失记录不可恢复属于存储失败，全部可恢复则属于检索失败。作者按失败类别分别抽样，把问题、答案、证据、当前输出和诊断结果连同设计及修改历史交给提案器，而不是只反馈一个总分。

作者让 LLM 提案器据此修改存储、检索或上下文构造，并解释修改理由。每个有效候选都重新构建记忆，在固定验证集上评分；只有二元正确率严格上升才接受，随后重跑训练集刷新诊断。回答模型、指令提示和最终上下文预算在设计间保持固定，每种设置执行20轮演化。作为具体实例，作者展示的一条轨迹包含九次被接受的修改：从原始问题的 BM25 检索，逐步加入稠密检索、混合检索与重排、问题分解、HyDE 和答案验证。最终方案使用四个 HyDE 查询、重排120个候选并读取25条记录，说明搜索确实改动了检索及上下文管线，而非仅更换记忆名称。

## 问答质量需要同时转化为检索与最终回答收益

作者在 ATM-Bench 的11,034条邮件、图像和视频记录上评估，主集有1,013题，困难多跳集有31题，回答器为 DeepSeek-V4-Flash。相对按记录索引、原问题检索并顺序填充上下文的 Base-BM25，生成监督驱动优化后，主集 Question Score 从54.9升至68.3，证据 R@10 从61.7升至84.1；困难集分别从8.2升至29.1、10.0升至43.6。QS 对数值题用精确匹配、列表题给部分分、开放题依赖裁判；R@10 则衡量前十条检索结果覆盖多少金标准证据。两类指标同步改善，支持优化不仅改善答案表述，也改善了证据获取。

在覆盖十个人设、21,142条交互记录的 RHELM 上，作者固定 GPT-4.1-mini 回答与评估，分别测试仅对话和加入邮件、文档两种条件。准确率由22.3升至26.4、由33.3升至39.9；但仅对话条件仍低于所列 RAG、k=50 的28.9。生成监督也使 M⋆、MemEvolve 在各自起点上取得6.0和18.6个主集 QS 点的提升，不过后者困难集 R@10 反降0.1点。与 Official-QA 的接近不能视为严格等条件胜出：该参照将训练及验证使用的官方题保留在评测中，而 MemSteer 未用官方评测题优化。ATM 条件下两者均用400条训练、200条验证监督。

作者的生成消融把“能生成问题”与“能提供有用监督”分开检验。完整 MemSteer 的双裁判平均 QA 质量为90.9%，未经检查时为75.4%；主集 QS 相应为68.3与65.2，但完整流程仅保留47.9%的候选。检查并非总提高下游表现：Ragas-QA 在困难集的 QS 从23.3降至20.7。另一项固定600个任务、来源记录、题型与生成模型的比较中，直接生成、同次响应生成计划与问题、分阶段检查计划后生成问题，质量分别为67.8%、73.1%、85.9%，每题 token 成本分别为64.0k、68.2k、105.1k。作者据此支持显式计划和分阶段检查，同时承认质量提升伴随更高生成成本；该比较使用共享过滤器，并非完整验证流程。

## 阶段诊断帮助搜索，共享设计仍需目标用户适配

作者进一步比较四种反馈：随机取最多30个失败案例、在此基础上增加参考证据、再增加失败阶段诊断，以及按三类失败各取最多十例。这里所谓 gold evidence 是生成监督中的参考来源，不是人工认证证据。作者报告，仅加入原始证据的收益有限，显式归因带来的改善更大，尤其体现在证据检索；诊断结合分层抽样取得最高下游 QS，但困难集的最高证据召回反而来自诊断加随机抽样。这个结果支持将证据转化为阶段性反馈，而不支持“召回最高必然回答最好”。抽取文本未提供该图各柱的完整数值，因此只能保留这一方向性比较。

作者的迁移实验揭示了继续适配的必要性。冻结 ATM-Bench 优化所得设计直接用于 RHELM，可将无外部数据准确率提高到26.4、有外部数据提高到38.6；在目标历史生成的监督上继续优化，分别达到30.6和42.8。但跨用户并非普遍受益：六用户共享设计在四个留出用户上的汇总准确率从35.3降至35.1，其中 Martin 从41.2降至37.7。用 Martin 自身历史生成监督继续优化后达到44.3；David 则从共享设计的38.6升至39.2。作者据此强调，历史生成监督的价值不只是替代人工标注，还在于让共享设计面对用户差异时有可用的继续优化信号。

## 适用条件与仍需验证的问题

已阅读抽取全文，未独立复现实验。阅读范围包含可用正文、参考文献与附录，但文本抽取不能保证图表、版式和公式忠实保留，也可能遗漏图像内部信息；反馈消融图与预算曲线未提供可完整核对的逐点数值。流程依赖远程 LLM API，作者也指出模型随机性和供应商更新会影响精确复现。Official-QA 参照包含优化时使用过的评测题，不能据其分数接近就认定生成监督在严格独立测试条件下等价于人工监督。

监督生成与验证均无人工认证，规划、审计和盲答模型共享的错误或偏差可能一起通过检查。盲答要求引用每条选定记录，只证明答案可从材料中恢复，并不证明每条记录都不可或缺；生成题分布来自历史内容，也不等同于用户真实的信息需求。评测仅覆盖两个基准，其中 RHELM 使用合成人设，困难多跳集仅31题；跨用户汇总结果还表明，共享设计对未见用户并无稳定收益。

MemSteer-Opt 的设计空间受限且主要围绕检索，本研究不能据此证明已解决长期记忆的在线更新、遗忘或冲突处理。较高质量监督需要更多 token，文中生成比较不构成端到端成本收益评估。作者还明确指出，个人记录会经第三方 LLM API 处理，跨记录组合生成的问答可能暴露敏感信息；应用于真实个人历史需要知情同意及相应隐私保护。
